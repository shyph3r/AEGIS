## 1. Docker Architecture

Docker uses a client-server architecture.

```text
User
 │
 │ docker command
 ▼
Docker CLI
 │
 │ Docker API
 ▼
Docker daemon (dockerd)
 │
 ├── manages images
 ├── creates containers
 ├── manages container networking
 └── manages container lifecycle
```

The Docker daemon runs as a Linux service:

```bash
systemctl status docker
```

The service was verified as:

```text
Active: active (running)
```

## 2. Docker Permissions

Initially, running:

```bash
docker ps
```

returned a permission error when attempting to access:

```text
/var/run/docker.sock
```

The current user was added to the `docker` group:

```bash
sudo usermod -aG docker $USER
```

After starting a new login session, Docker commands could be executed without `sudo`.

Membership in the Docker group provides significant control over the host and should therefore be treated as a security-sensitive permission.

## 3. Images vs Containers

A Docker **image** is a template containing the files, dependencies, and configuration required to run an application.

A **container** is a running or stopped instance created from an image.

```text
IMAGE
  │
  │ docker run
  ▼
CONTAINER
  │
  ▼
PROCESS
```

One image can be used to create multiple containers.

---

## 4. First Container

I tested the Docker installation using:

```bash
docker run hello-world
```

Because the `hello-world` image was not available locally, Docker downloaded it and created a new container from it.

The container executed its main process, printed a message, and then exited.

I inspected all containers using:

```bash
docker ps -a
```

The container appeared with:

```text
STATUS: Exited (0)
```

Exit code `0` indicated that the process completed successfully.

---

## 5. Images

Installed Docker images were inspected with:

```bash
docker images
```

The `hello-world` image remained available even after its container stopped.

This demonstrated that an image and a container have separate lifecycles:

```text
hello-world IMAGE
       │
       │ docker run
       ▼
hello-world CONTAINER
       │
       ▼
main process executes
       │
       ▼
process exits
       │
       ▼
container stops

IMAGE remains available
```

## 6. Container Logs

The output produced by the container was inspected using:

```bash
docker logs <container-name>
```

This returned the output generated by the container's process.

Container logs will later be useful when investigating application behavior and security events.

## 7. Long-Running Containers

The `hello-world` container stopped because its main process completed.

A long-running application such as a web server behaves differently:

```text
Container starts
      ↓
Web server process starts
      ↓
Process continues listening
      ↓
Container remains running
```

This demonstrates an important relationship between containers and processes:

```text
Container
    │
    └── Main process
            │
            ├── running → container remains running
            │
            └── exits   → container stops
```

## 8. Docker Port Mapping

Containers have their own isolated network environment.

A service listening on a port inside a container is not the same as a service listening directly on the Ubuntu host.

Docker can publish a container port using:

```text
-p HOST_PORT:CONTAINER_PORT
```

For example:

```bash
docker run -d --name aegis-web -p 8080:80 nginx
```

means:

```text
Ubuntu host port 8080
          │
          │ Docker port mapping
          ▼
Container port 80
          │
          ▼
nginx process
```

The external communication path is therefore:

```text
Kali Attacker
192.168.219.10
       │
       │ HTTP request
       ▼
Ubuntu Target
192.168.219.20:8080
       │
       │ Docker port mapping
       ▼
Container
TCP port 80
       │
       ▼
Web server process
```

## 10. Commands Used

Check Docker version:

```bash
docker --version
```

Check Docker service:

```bash
systemctl status docker
```

Show running containers:

```bash
docker ps
```

Show all containers:

```bash
docker ps -a
```

Show local images:

```bash

```

Run a container:

```bash
docker run hello-world
```

View container logs:

```bash
docker logs <container-name>
```

---

## Key Takeaways

- An image is a template used to create containers.
- A container is an isolated runtime environment created from an image.
- Containers normally depend on a main process remaining active.
- Docker Engine is managed by the `docker.service` systemd service.
- The Docker CLI communicates with the Docker daemon.
- `docker ps` displays running containers.
- `docker ps -a` also displays stopped containers.
- `docker images` displays locally available images.
- `docker logs` displays output generated by a container.
- Docker port publishing maps a host port to a container port.
- Docker containers use the Linux kernel of the host rather than running a complete guest operating system.
